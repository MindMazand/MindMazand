# پیاده‌سازی مرکز ورود و بازبینی Excel — مرحله ۰.۳

## هدف
این مرحله اولین مسیر ورود فایل Excel به برنامه دسکتاپ را پیاده می‌کند، اما عمداً ورود به جداول عملیاتی را انجام نمی‌دهد. مسیر فعلی فقط فایل را می‌خواند، شیت را انتخاب می‌کند، پیش‌نمایش می‌دهد و ردیف‌ها را در صف `PREVIEW` ذخیره می‌کند.

## رفتار برنامه
1. فقط مدیر سیستم (`ADMIN`) یا مدیر مجموعه (`MANAGER`) می‌تواند وارد مرکز ورود فایل شود و فایل `.xlsx` یا `.xls` را انتخاب کند.
2. برنامه اثرانگشت SHA-256 فایل را محاسبه می‌کند.
3. نام شیت‌ها، تعداد ردیف‌های غیرخالی و تعداد ستون‌ها خوانده می‌شود.
4. حداکثر ۲۵۰ ردیف برای پیش‌نمایش در UI نمایش داده می‌شود.
5. سقف فعلی هر شیت ۱۰٬۰۰۰ ردیف غیرخالی و حجم فایل ۵۰ مگابایت است.
6. پیش از ذخیره و پیش از Commit تراکنش، SHA-256 دوباره محاسبه می‌شود؛ اگر فایل تغییر کرده باشد عملیات لغو می‌شود.
7. با انتخاب «ذخیره در صف بررسی»، کل ردیف‌های شیت انتخابی در یک تراکنش SQLite ذخیره می‌شوند.
8. JSON پاک‌سازی‌شده در `raw_row_json` فقط منشأ، شماره ردیف و تعداد ستون را نگه می‌دارد.
9. محتوای سلول‌ها در `raw_sensitive_enc` با DPAPI و محدوده `CurrentUser` رمزگذاری می‌شود.
10. وضعیت همه ردیف‌ها `PENDING` و وضعیت بسته `PREVIEW` است.
11. هیچ فاکتور، سند مالی، حرکت انبار، تأیید یا مانده عملیاتی ایجاد نمی‌شود.

## محدودیت‌های عمدی
- این نسخه هنوز پروفایل‌های تخصصی برای هر چهار فایل مازندشت را اعمال نمی‌کند.
- تشخیص تاریخ نامعتبر، ردیف نمونه، کلیدهای مرجع و تکراری‌های معنایی هنوز در لایه پروفایل‌های مرحله بعد انجام می‌شود.
- این نسخه هیچ ردیفی را خودکار قبول یا رد نمی‌کند.
- داده رمزگذاری‌شده با DPAPI `CurrentUser` به همان پروفایل کاربری ویندوز وابسته است؛ بازیابی payload صف واردسازی روی ویندوز/حساب کاربری دیگر بدون سازوکار انتقال کلید ممکن نیست. این موضوع برای نسخه نهایی باید با سیاست کلید سازمانی تعیین تکلیف شود.
- این قابلیت هنوز در محیط فعلی با MSBuild ویندوز کامپایل نشده است.

## امنیت و حفاظت داده
- فایل منبع فقط با دسترسی خواندن باز می‌شود.
- فایل اصلی بازنویسی نمی‌شود.
- فایل‌های دارای اطلاعات بانکی/شخصی باید محرمانه نگهداری شوند.
- ردیف خام در ستون متنی بدون رمزگذاری ذخیره نمی‌شود.
- ثبت batch و rowها در یک تراکنش انجام می‌شود؛ در خطا، تراکنش rollback می‌شود.
- ورودی‌ها پارامتری هستند و SQL از الحاق مقادیر سلول‌ها ساخته نمی‌شود.

آزمون‌های Python قرارداد اسکیمای staging، نگهداری payload رمزگذاری‌شده، XML و اتصال event handlerها را بررسی می‌کنند. این آزمون‌ها جایگزین build واقعی WPF یا آزمون DPAPI در ویندوز نیستند.

## الحاقیه مرحله پنجم — پروفایل و نگاشت ستون‌ها

در نسخه `0.5.0-alpha1`، مرکز ورود Excel از حالت عمومی به ۱۱ پروفایل ماژول‌محور توسعه یافته است. برای هر پروفایل قالب خالی همراه فرهنگ داده ارائه می‌شود. عنوان‌های یکسان به‌صورت اولیه خودکار تطبیق داده می‌شوند و کاربر می‌تواند ستون منبع را در جدول نگاشت اصلاح کند. فیلدهای الزامی باید به یک ستون منبع متصل شوند.

نگاشت JSON و شماره ردیف عنوان در `import_batches` با migration 004 ذخیره می‌شود. اولین ردیف غیرخالی شیت، ردیف عنوان محسوب می‌شود و از ردیف‌های payload عملیاتی صف کنار گذاشته می‌شود.

اعتبارسنجی محتوایی و Commit نهایی هنوز فعال نیست؛ صف `PREVIEW` صرفاً ورودی رمزگذاری‌شده و نگاشت تأییدشده را نگه می‌دارد و هیچ سند عملیاتی یا مالی ایجاد نمی‌کند.
